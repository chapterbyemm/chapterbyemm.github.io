Editor's Manual

How to change photos, prices, products and text on the site — without touching anything that can break it. No coding experience needed.

START HEREThe one file that matters

Almost everything you'll ever want to change lives in a single file:

assets/js/data.js

Prices, product names, descriptions, which photos appear, your WhatsApp number, the announcement bar — all of it. You can edit this file directly on GitHub in your browser.

How to edit any file on GitHub

  1. Open the file in your repository
  2. Click the pencil icon (top right of the file)
  3. Make your change
  4. Scroll down, click Commit changes

Your site updates within a minute or two. That's the whole loop — every task below is a variation on it.

The one rule: keep punctuation exactly as you found it. Every line needs its quotes " and its comma at the end. If something breaks, the products stop appearing — undo your last commit and the site comes straight back.

TASKSwap a product photo

The safest method: give the new photo the same filename as the old one. Then nothing else needs changing.

  1. Rename your new photo on your computer to match the one you're replacing — for example calm-superpower-1.jpg
  2. Go to assets/img/products/
  3. Add file → Upload files, drag it in
  4. Commit changes — it overwrites the old one

TASKChange a price or description

Open assets/js/data.js and find the product by name. Each one looks like this:

{
  id: "calm-is-a-superpower-tee",
  name: "Calm Is a Superpower Tee",
  price: 2400,
  compareAt: null,
  ...
}
  • price — just the number. No commas, no Rs. Write 2650, never 2,650
  • compareAt — set this to the old price to show a sale strike-through. Use null for no sale
  • name and description — plain text inside the quotes
  • badge — "New", "Best Seller", "Limited", or null

To put something on sale: set price to the new lower number and compareAt to the original. The site handles the strike-through and the discount badge automatically.

TASKAdd a brand-new product

Upload the photos first, then add the product entry.

1. Upload the photos

Put them in assets/img/products/. Name them in a simple, consistent pattern — lowercase, hyphens instead of spaces, no capitals or spaces ever:

soft-heart-1.jpg
soft-heart-2.jpg

2. Copy an existing product block

In data.js, copy one whole product block (from its opening { to its closing },), paste it directly below, then change every field:

{
  id: "soft-heart-tee",
  name: "Soft Heart Tee",
  price: 2400,
  compareAt: null,
  categories: ["new-chapters", "everyday"],
  images: [
    "assets/img/products/soft-heart-1.jpg",
    "assets/img/products/soft-heart-2.jpg",
  ],
  colors: ["cream"],
  sizes: SIZES_ALL,
  soldOut: [],
  badge: "New",
  description:
    "A short, warm sentence about this design.",
  fabric: "100% cotton, 200 gsm.",
  fit: "Relaxed oversized fit.",
  care: "Cold machine wash, inside out. Do not tumble dry.",
  rating: 5.0,
  reviewCount: 0,
},

3. Use only these values

Colours — pick from this list (the key on the left, not the label):

Sold out sizes: put them in the soldOut list to cross them out on the product page — for example soldOut: ["XS", "XXL"],

BEFORE LAUNCHStill to be filled in

These are real placeholders in the site right now. Everything works, but these say the wrong thing until someone updates them.

  • WhatsApp number. Currently 923000000000, which is not a real number. In data.js and in custom-designs.html. Until it's changed, every "message us" button goes nowhere.
  • Contact + custom-order forms. They need a free Formspree account. Sign up, create a form, and replace YOUR_ID in assets/js/app.js. Until then, submissions aren't delivered anywhere.
  • Fabric, fit and care. Each product has [EDIT] notes for these. Fill in your real composition, GSM, print method and wash instructions. Don't leave invented specifics like "organic cotton" unless it's true.
  • Shipping and returns pages. Both carry [EDIT] markers — delivery timeframes, charges, and your returns window need your real policy.
  • Privacy and terms. Templates only. Have someone read them before you take real orders.
  • Business email. Currently hello@chapterbyemm.com — confirm this is a real inbox someone checks.

IF SOMETHING BREAKSUndoing a change

Nothing you do here is permanent. Every change is saved separately and can be reversed.

  1. Go to the Commits list in your repository
  2. Find the change that caused the problem
  3. Open it and click Revert

The site returns to exactly how it was. If products vanish from the shop page, it's almost always a missing comma or quote mark in data.js — revert, then try the edit again more slowly.

A good habit: change one thing, commit, check the site. Small commits are far easier to undo than one big one.

Every task here is done in the browser on GitHub — nothing needs installing. The one job that needs outside help is connecting a real payment gateway; everything else on this page is yours to change.
